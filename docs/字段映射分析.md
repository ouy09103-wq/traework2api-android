# 阶段2 第1步：字段映射分析（OpenAI ↔ TraeWork SOLO）

> 结论来源：`reference/traework2api`（Go 网关，**已实测**）源码，
> 以及 `reference/WorkBuddy2API-Android`（Kotlin/Android，直连 Trae 上游）。
> 本工程（Android 小白版）就是把"本地 HTTP 端口 + 转发 Trae"做进 Android，字段规则以本文件为准。

---

## 1. 一句话原理

手机上的 TraeWork2API 在本地端口（如 8788）开一个 HTTP 服务，收到任何 OpenAI 客户端发来的请求后：

1. 把 **OpenAI 格式**改写成 **Trae SOLO 格式**，带上你的 **access_token**，发到 Trae 的官方代理；
2. 收 **Trae 的流式事件**，逐条映射回 **OpenAI 流式事件**，回给客户端。

---

## 2. OpenAI 请求 → Trae 请求（字段映射）

核心参考：`reference/traework2api/internal/upstream/payload.go::PrepareBody`

| OpenAI 客户端发来的字段 | 去向（Trae 侧） | 说明 |
|---|---|---|
| `model` | `config_name` + `mode`（两者同值） | 空则用默认 `glm-5.2`。也支持 `__dev`/`__max` 内部名后缀、下划线↔横线宽松匹配 |
| `stream` | 强制 `true` | 上游只认流式，非流式由本端聚合 |
| *(无)* | 新增 `function: "solo_work_lite"` | 固定值 |
| `messages[].content`（字符串） | 改成 `[{"type":"text","text":...}]` | 已是数组则原样透传（多模态保守透传） |
| `messages[].role=assistant` 的 `tool_calls[].function` | 改成 `function_call` | 无 name 的工具调用被剔除 |
| `tool_choice` | 归一化为字符串 | `none`→删掉+删 tools；`auto`/`required`→保留；`function`→提取 name；其他→删 |
| `tools[].function.parameters`（对象） | JSON **字符串**化 | Trae 上游 struct 该字段是 string |
| `temperature` / `max_tokens` / `top_p` / `presence_penalty` / `frequency_penalty` | **原样透传**（不改） | 代码未额外处理 |
| 请求体大小 | 上限 8MB，超了回 413 | |

**请求 URL 与鉴权头**（`headers.go::SOLOHeaders`）：

```
POST https://trae-api-cn.mchost.guru/api/agent/v3/llm_utils_chat
Content-Type: application/json
Accept: text/event-stream        (流式时)
User-Agent: Trae/0.1.43
Authorization: Cloud-IDE-JWT <access_token>
X-Cloudide-Token: <access_token>
X-Ide-Token: <access_token>
X-Uid: <uid>                     (若有)
X-App-Id: 6eefa01c-1036-4c7e-9ca5-d891f63bfcd8
X-Ide-Version: 0.1.43
X-Ide-Version-Code: 20260716
X-Device-Type: windows
X-OS-Version: Windows 11 Pro
X-Device-Brand: 83DG
X-Device-Id: <device_id>         (若有)
X-Machine-Id: <machine_id>       (若有)
X-App-Version: default
X-Ide-Version-Type: stable
Request-Traffic-Type: prod
```

> ⚠️ 这些头里 **access_token 是敏感信息**，绝不能写进日志/源码。Auth 数据本身属于账密凭据维度——本工程要用 Android 加密库存，见后续阶段。

## 3. Trae 响应 → OpenAI 响应（映射）

### 3.1 Trae 上游事件序列（`solosse.go` 头注释）

```
event:metadata     data:{"model":"","session_id":"...","prompt_completion_id":0,...}
event:timing_cost  data:{"name":"llm_raw_chat_v2",...}
event:output       data:{"response":"<增量>","reasoning_content":"<思考链增量>","tool_calls":<null|...>}   ← ×N 核心
event:extra_info   (含完整 reasoning)
event:token_usage  data:{"prompt_tokens":..,"completion_tokens":..,"total_tokens":..,"reasoning_tokens":..}
event:done         data:{"finish_reason":"stop"}
event:error        data:{"code":..,"message":".."}
```

### 3.2 逐事件 → OpenAI chunk（`streamOpts` L318-L444）

| Trae 事件 | 写到 OpenAI chunk 的位置 |
|---|---|
| `output.response` | `choices[0].delta.content` |
| `output.reasoning_content` | `choices[0].delta.reasoning_content` |
| `output.tool_calls[].function_call` | `choices[0].delta.tool_calls[].function`（name/arguments，arguments 流式拼接） |
| `token_usage` | 暂存，追加在**最后一个** chunk 的 `usage` |
| `done.finish_reason` | 写空的 chunk 只带 `choices[0].finish_reason` |
| 结束 | 写 `data: [DONE]` |
| `error` | 写 `event: error` + `data: [DONE]` |

OpenAI chunk 外壳：

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion.chunk",
  "created": <unix> ,
  "model": "",
  "choices": [{ "index": 0, "delta": { "content": "...", "reasoning_content": "...", "tool_calls": [...] } }]
}
```

> 注意：Trae 清洗掉 `namespace` / `partial_arguments` 等 SOLO 专属字段，只留标准 OpenAI function 结构。

### 3.3 非流式（`stream=false` 时本端聚合，`Aggregate` L143-L223）

把所有 `output` 拼成完整 `content` / `reasoning_content`，`tool_calls` 按 `index` 合并 `arguments`，包成：

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "created": <unix>,
  "model": "",
  "choices": [{ "index":0, "message": {"role":"assistant","content":"...","reasoning_content":"...","tool_calls":[...]}, "finish_reason":"stop" }],
  "usage": {...}
}
```

## 5. 登录 / Token 刷新链路（后续阶段用）

| 意义 | 端点 |
|---|---|
| 码换 token | `POST https://api.trae.com.cn/cloudide/api/v3/trae/oauth/ExchangeToken` |
| 用户信息 | `POST https://api.trae.com.cn/cloudide/api/v3/trae/GetUserInfo` |
| **刷新 access_token** | ExchangeToken 带 `RefreshToken` + `ClientID` + `ClientSecret:"-"`，请求体含 `{"ClientID":...}` |
| 签到/积分（阶段3才做） | `https://api.trae.cn/trae/api/v2/ug/checkin_credits/...` |

## 6. 本工程 Android 落地要点（阶段2 实现时）

- 端点在 Android：监听 `0.0.0.0:8788`，路由 `POST /v1/chat/completions`、`GET /v1/models`、`GET /healthz`。
- **本地鉴权**：客户端需带 `Authorization: Bearer <本地APIKey>`，与上游 access_token 是**两套**，本地 Key 不接触 Trae。
- 上游依赖 `okhttp`（阶段2 引入）做 HTTPS 转发与 SSE 读取。
- 模型转换、SSE 解析逻辑：把上面 Go 的 `PrepareBody` / `ParseSOLOLine` / `streamOpts` / `Aggregate` 用 Kotlin 复刻。
- 单账号先做（多账号/轮转是后续增强）。
